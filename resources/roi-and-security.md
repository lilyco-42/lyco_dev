# ROI 决策排序、零信任边界与异常 Fallback 规范

## 1. ROI 三级评估顺序
每次架构或需求取舍，按以下顺序打分（这是 ROI 支柱**内部**的权衡顺序，六大支柱之间仍并列同等重要）：
1. **第一优先 · 商业价值**：是否直接带来营收、转化、留存或堵住资金/盗刷漏洞？协议是否 100% 可商用？
2. **第二优先 · 社会效益与贡献**：是否能沉淀为开放标准、高质量开源工具或可复用 Skill？
3. **第三优先 · 开发敏捷度**：**参考成熟商业方案交付可用 MVP**，尽快交到用户手中校对真实需求，验证后再迭代；不过早做无用户验证的复杂抽象，也不交付残缺的玩具 Demo。

## 2. 零信任类型边界（防注入与防类型擦除）
- **后端入参**：
  - 所有外部输入必须反序列化为明确强类型结构体，默认加上 `#[serde(deny_unknown_fields)]`。
  - 使用 `newtype` 封装敏感领域值（如 `UserId(i64)`、`PaidCredits(u64)`、`Slug(String)`），在构造点完成长度、字符集、范围校验。
  - **禁止**把 `serde_json::Value` 当作业务函数参数在后端内部到处传递（杜绝类型擦除）。
- **前端出参**：
  - 前端必须根据后端 API 契约完成显式类型转换与基础消毒（trim、数值范围、XSS 转义），不随意透传未定义字段。

## 3. 生产级异常 Fallback 清单
| 异常场景 | 必须具备的 Fallback 与报错策略 |
| --- | --- |
| **服务器突然断电** | 数据库开启 WAL + 原子事务（先写账本流水再变更状态）；重启后自动回滚/恢复悬挂的预扣记录 |
| **用户中途断网 (EOF)** | 流式接口（如 SSE）在 Drop/EOF 时按已实际发送的 token/字节数精确结算，防止零扣费白嫖 |
| **上游超时 / 429 / 5xx** | 自动熔断冷却故障渠道并无缝切换备用渠道；全部失败时退还预扣额度并返回明确上游状态码与追踪 ID |
| **非法输入 / 越权 / 余额不足** | 返回结构化 JSON 错误（`error_code` + 中文/英文可读原因 + 修复指引），绝不返回模糊 `500` 或触发 `panic!` |

## 4. 高价值资源防刷底线
- **双钱包隔离**：免费/签到/活动积分（`bonus_points`）仅限可复制数字资源（素材/文档/软件）；不可复制高成本资源（AI 算力、代理专线、VIP 订阅）**仅限实付余额（`paid_points`）**。
- **邀请返佣防薅**：仅在被邀请人真实实付充值入账后触发返佣，并关联订单号支持退款自动冲正。
